title=Area Export

description=Admin-only migration utility for Project Zomboid Build 42. Export a circular world area from one save or server and import it into another save at the original world coordinates.
description=
description=Alpha warning: Area Export is currently a first public alpha version. It can still contain bugs and can cause world-data problems if an import hits unsupported Project Zomboid object state. Always back up the target save and test on a local or disposable server before using it on a live server.
description=
description=Designed for base migration, server resets, recovery tests, and controlled admin workflows.
description=
description=Features:
description=- Export by center point and radius.
description=- Save local export packages on the admin PC.
description=- Import at the original world coordinates and original export radius.
description=- Preserve many tiles, walls, doors, furniture, containers, stored items, loose floor items, player-built structures, and selected object state.
description=- Rebuild interactive vanilla object classes for TVs, radios, stoves, microwaves, washers, dryers, BBQs, fireplaces, jukeboxes and composters instead of restoring them as static sprites.
description=- Validate / Dry Run before import to group missing item, sprite, object, and incomplete legacy door conflicts.
description=- Replace, skip, or keep placeholder items for missing item types.
description=- Use original, replace, or skip sprite lookup warnings.
description=- Dry Run and Import progress bars for package scans, upload, footprint clearing, and tile rebuild phases.
description=- Automatic post-import reconcile for loose floor-item client ghosts.
description=
description=Important: importing is destructive inside the exported footprint. Always back up the target save and test on a local or disposable server before using this on a live server. Do not import while players are active in the target area.
description=
description=Special object notes: Project Zomboid gates many interaction menus behind Java object subclasses. A TV, radio, stove or dryer restored as a plain IsoObject can look correct but will not open its normal UI. Area Export detects those classes during export and also infers them from sprite IsoType/container data during import for older packages.
description=
description=Build 42 live imports also need targeted entity/component initialization for stoves, laundry machines, TVs and radios before rebuilt objects are transmitted. TVs and radios additionally need DeviceData from the tile CustomItem or matching TV/radio item type after object initialization, otherwise the sprite and IsoTelevision/IsoRadio class can persist but the device panel will not open.
description=
description=Dedicated servers cache loaded Lua modules. After a mod update, restart the server process before retesting imports; reconnecting only the client does not reload server-side import code.
description=
description=Current limitations: vehicles, zombies, and player inventories are not migrated. State-heavy special objects such as generators, mannequins and feeding troughs are flagged by Dry Run object conflicts until separate state mapping is added.
description=
description=Memory notes: Export, Dry Run and Import use a package format instead of one giant JSON string. Export writes tile JSON lines directly to disk on the admin PC. Dry Run scans those lines one tile at a time while showing checked package tiles. Import uploads the package into a temporary server-side tile file first, then clears and rebuilds the target footprint over later ticks. During clearing, linked double-door and garage-door parts are removed as one group so partial door objects do not survive at footprint edges. Live door sync is conservative: rebuilt doors are transmitted as complete objects, but generic syncIsoObject packets are avoided for doors because Build 42 can reject freshly rebuilt live door indexes. Garage door parts are restored as a closed linked group instead of toggling each part during import. Import progress is phase-based and resets for upload, footprint clearing, and tile rebuild. Very large areas can still take time and may briefly stall while individual tiles with many objects or items are processed.
